## 三、原因分析

1. **字数被当成硬门槛，而且口径不一致。** 目录里的字数是人工估的（08 页写 774，脚本按 SVG 实际数出 619）。规则规定"少一半或多 30% 就换页"，结果循环类（33、06、49、50）和层级类（42、04）整类被排除，退到通用版式。P3、P5 的错配就是这样来的。这里是逻辑让位给了字数。
2. **候选太少，又有"一页只用一次"和"相邻页不用同一种主图示"的限制。** 循环类 4 页、层级类 2 页、数据面板 3 页。P3 退到数据面板时，三页已经被别的页用掉，只能用"多项并列"的 19。
3. **目录只描述了主图示，没有描述部件的含义。** "含义提醒"一栏只有一句话，没有逐个列出箭头、颜色、环、光束、`+`、向上 / 向下箭头、圆的大小这些部件各自表达什么。规划和 fork 改页时只做"换字"，部件的含义被原样带过来（第二节第 2 类）。
4. **一页只取一个主逻辑，但大纲页通常是复合的。** 例如 P2 = 漏斗 + 卡点→解法映射 + 对照漏斗 + 关键数字；P6 = 两方 × 四维对比 + 逐年柱图。只按主逻辑选页，次级关系没有落点，只好塞进蓝图里碰巧有的格子（例如 P6 的维度被放进环）。
5. **规划表的"主图示怎么对应内容"只有一句话，没人校验。** v3 的 plan.md 里，P6 写的是"右侧圆 = FDE 驱动，圆心 = NRR"。这一行没有回答"环上的节点代表什么、是否真有循环"，fork 照做后就成了错配。
6. **复用率门槛（低于 50% 就重新起页）在保护错误部件。** 删掉含义不对的部件会拉低复用率。P4 没敢移动 KPI 框，P1 为了对齐锚点把行距拉大。
7. **渲染自检只查版面，不查含义。** 第 7 步只列溢出、压字、裁切、低对比和残留，没有"这个图形读出来的意思是否等于大纲"这一项。规划者和改页者都是同一份上下文，也难以发现自己的错配。
8. **图标没有进入规划。** 图标库选择、页头图标和每个模块的图标都没有逐项按含义确定，第二节第 3 类由此而来。
9. **`start_page.py` 删除了所有 `<image>`。** 照片该删，但参考稿里的矢量小图标和页头手形也是 `<image>`，一并删掉了。

## 四、建议的下一步（按优先级）

> 下面都还没有实施。改 Skill 前要先经用户同意，`catalog.md` 也还要用户审定。

### P0　先做"选图基准"，不再用整稿测试来调选图
- 从 s11 和另外两三份大纲里挑 15–20 页。由用户为每页标注"应选的蓝图页"和"不可用的页及原因"，作为标准答案，放在 `Sam-PPT-Lab\` 下。
- 只跑第 1–2 步（读目录、写规划表），不起页、不导出。每次 2–3 分钟，就能量出选图准确率和部件错配数，改规则后可以快速回归。整稿测试一次 17 分钟，不适合用来调选图。

### P1　目录改造：从"逻辑 → 页"改成"内容结构 → 页，加部件含义"
- 每个推荐页补充**结构签名**：对象数、维度数，是否有顺序 / 循环 / 递减 / 层级 / 因果 / 对照。选图时，先把大纲页抽成同样的结构签名再匹配，不再只判断一个"主逻辑"词。
- 每个推荐页补充**部件含义表**：逐个列出可见部件（箭头、环、光束、`+`、上下箭头、红蓝配色、圆的大小、连线），写明它表达什么、内容不满足时是删还是改。例如：07 页"环上节点 = 循环的步骤，只有真有循环时保留"；"`>>>` = 从左转变到右"。
- **字数只用来在候选之间排先后，不再淘汰候选。** 目录字数改用脚本统一计算（和 `start_page` 起页后的 `<text>` 统计口径一致），不再人工估计。
- 允许**主图示加一个次图示**的组合（例如漏斗 + 映射表）。目录标出每页哪块区域可以安全替换成次图示。
- 放宽"同一页最多用一次"：同类候选不够时，允许同一蓝图页再用一次（换配色或镜像），优先于退到通用版式。也可以从"不推荐"里补候选，例如为循环、层级两类各补 1–2 页（要先给用户看）。

### P2　规划表加强，并加一道独立的含义审查
- 规划表每页增加三列：
  - **保留部件及其含义是否成立**
  - **要删除的含义部件**
  - **图标（模块 → 图标 → 理由）**
- 写完 plan.md 后，开一个**不带规划上下文**的子代理只做审查。给它 `outline.md`、蓝图渲染图、规划表和目录的部件含义表，让它逐页回答"这页图形读出来是什么意思，和大纲是否一致"。有不一致就改规划，然后才起页。
- 第 7 步渲染自检加一项"含义核对"：看着渲染图，把每个箭头、环、颜色、强调读一遍，和大纲对照。

### P3　复用率门槛改为提示
- 低于 50% 时只要求在日志里写明原因，不再强制重新起页。删掉含义不对的部件是正当理由。

### P4　图标
- **页头手形**：两个方案，需要用户选一个。
  - 方案一：`start_page.py` 不再删除矢量 `<image>`（`.svg`），把对应文件复制到项目的 `images/` 里，原样保留参考稿的手形和小图标。改动前要实测 ppt-master 检查和导出是否接受。
  - 方案二：页头固定用 `chunk-filled/hand`（或 `hand-tap`），作为"只用一个图标库"规则的例外。
- **模块图标**写进规划表，并在审查里一起核对。考虑参考稿原图标的风格，评估改用 `chunk-filled` 是否更接近。

### 其他遗留（不属于选图，但别丢）
- **用时**：v3 是 17.1 分钟，目标是 10 分钟以内。最大的单项是读目录和写规划（4.3 分钟）和主代理自己写的第 1 段（8.6 分钟）。
- **质感**：起页时随图片丢掉了约一半的渐变、阴影和半透明。第 P4 条的方案一可能顺带改善一部分。
- **v3 剩余问题**：P7"健康线"被线擦到，P8 装饰线穿过阶段名，P4 右栏留白，P1 页面偏疏。
- **来历不明的文件**：v3 运行目录里出现过一个 `deck - Copy.pptx`，测试会话报告说来历不明，还没查清。
- **目录待审定**：`catalog.md` 末尾有 4 个"待用户确认的点"。
