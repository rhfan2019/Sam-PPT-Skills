# 研究报告：PPT 逻辑表达规范与页面模块化组合（2026-10-27）

> 状态：**历史，已实施**（2026-10-27，提交 6992530 起）。本文说明为什么改成按关系选图、跨页拼模块；现行规则以 `Sam-PPT-Blueprint/references/` 为准，未完成事项已并入[待办清单](../plans/backlog.md)。文中提到的 `seed.py` 已停用。

## 摘要

三次隔离测试都出现了同一类错误：大纲要表达的关系，和页面上的图示、部件、图标对不上。例如四步循环被做成清单，"底座 / 上限"没有层级图形，四个对比维度被画到循环环上，表示改善却用了红色向下箭头。

问题出在方法上，不是选错了哪一页。"一页照搬一张参考页"的做法有两个缺陷：
- 没有一套"什么关系用什么图"的规范，选图只能凭感觉。
- 参考页本身是复合版面（主图示、数据卡、结论栏、装饰），整页搬过来，各部件原有的含义也被一起带了进来。

本次研究了两件事，并已写进 Skill：

1. **逻辑表达规范**：整合了 Zelazny、Abela、FT、SmartArt、Duarte、Periodic Table、咨询稿惯例和中文 PPT 分类，得到五大族 29 种关系，外加 5 种战略框架。每种关系都写明了四项：判断标准（全部满足才算）、首选图示、必备部件、禁用部件。另外整理了 23 种部件的固有含义、17 条删改规则、"方向跟数值、颜色跟好坏"的配色规则，以及复合页面的主次规则。
2. **页面分区与模块组合**：一页不再固定照搬一张参考页，做法改为：
   - 按主关系选分区模板（10 个，坐标取自参考稿实测的 12 栏栅格）；
   - 每个分区从参考稿拆出的模块目录里挑一个模块，模块可以来自不同的页；
   - 用新工具 `compose_page.py` 拼成一页，保留原模块的坐标、渐变、阴影和装饰。

另外，研究过程中发现并修好了两个底层问题：
- **导入后变形**：参考稿有些效果导入后会变形，例如第 33 页的立体光环会变成覆盖半页的大圆。现在选模块以"起页后渲染图"为准，不再看原稿截图。
- **图标丢失**：页头手形和参考稿的小图标原来随图片一起被删掉。现在这些矢量图标会转成原生可编辑形状保留下来。

## 一、问题回顾

| 测试 | 选图方式 | 典型错配 |
|---|---|---|
| v2 | 临场从 65 页中选 | 岗位定义用了倒金字塔；循环页的中心是一座房子（原稿意思是"智能家居"） |
| v3 | 按版式目录逐页选 | 循环页做成 8 卡清单；"底座 / 上限"做成数据面板；四个对比维度放在循环环上；改善用红色向下箭头；风险页用增长箭头装饰；页头手形变成箭头光标 |

根因有四条：
1. 没有"关系 → 图示"的判断标准。
2. 整页照搬，部件的含义也被一起带了进来。
3. 字数被当成硬门槛，候选不够就退回通用版式。
4. 没有人从读者的角度检查图示表达的意思。

## 二、ppt-master 已经有什么，缺什么

按仓库约定，先查底层引擎已有的能力，已有的不重造。

| ppt-master 已有 | 位置 | 本次的处理 |
|---|---|---|
| 33 种数据图表的"编码了什么关系"词表 | `templates/charts/chart-vocabulary.md` | 直接引用，不重写 |
| 表格词表（对比矩阵、评分矩阵等） | `templates/tables/table-vocabulary.md` | 直接引用 |
| 6 个关系原子（order、link、parent、membership、contrast、overlap）和拓扑组装规则 | `references/executor-structure.md`、`topology-assembly.md` | 在总表里给出每种关系对应的原子 |
| 6 种"内容关系 → 起始版式"（单焦点、等权对比、主证据加结论等） | `references/executor-base.md` Page Expression Core | 扩展成 10 个分区模板，坐标改用参考稿实测栅格 |
| 11 种信息图类型（循环、漏斗、金字塔等），只用于 AI 生图 | `references/image-type-templates/` | 不适用（本路线不生图） |

**ppt-master 缺的、也是本 Skill 要补的**：
1. **命名业务图示的判断标准和禁用部件。** ppt-master 刻意不设"结构目录"（"never recall a named diagram"），要求执行者从关系原子现场生成。这适合从零画图；但本 Skill 是从参考稿借图，借来的图示自带含义，必须有一张"这个图形在说什么、什么时候不能用"的表。
2. **部件级的含义检查。** ppt-master 的验证项是覆盖、阅读路径、角色，没有"参考稿带来的箭头、光束、`+` 号是否还成立"这一层。
3. **跨参考页的模块组合。** ppt-master 的 layout 模板以整页为单位；没有从多张参考页各取一块拼成一页的工具。

## 三、逻辑表达规范（要点）

详细内容在 Skill 的 `references/logic-diagrams.md`，研究笔记（含全部来源）在 `runs\20261027-0842_logic-research_rnb\research-logic-diagrams.md`。

### 1. 三条总原则
- 先定信息，再定关系，最后选图（Zelazny）。
- 图形部件本身就带含义，换图形就是换说法（Microsoft SmartArt 官方说明；Tversky 等的认知研究：带箭头的图被读成过程或因果，不带箭头的被读成结构）。
- 内容里没有的关系，图上就不能画；拿不准时退回并列卡片或表格。

### 2. 关系分类：两个问题定族
- 单元之间有没有方向？
- 单元之间是否等权？

| 族 | 关系 |
|---|---|
| A 并列（无方向、等权） | 并列清单、总分 / 中心辐射、交集、包含 |
| B 序列（有方向） | 流程、阶段演进、**循环**、时间线、**甘特**、路线图、**漏斗**、分流 / 汇聚 |
| C 结构（不等权、有上下） | **层级依赖**、组织结构、因果拆解（问题树、鱼骨）、驱动因素 |
| D 比较 | 两方对比、**多方 × 多维**、前后对照、排名、2×2 矩阵、权衡、偏差 |
| E 数量（有数据） | **构成占比**、趋势、分布、相关、瀑布桥接、微笑曲线 |
| F 战略框架 | 战略屋、OGSM、战略地图、价值链、五力 |

### 3. 用户点名的几类

| 关系 | 判断标准 | 用什么图 | 不能怎么画 |
|---|---|---|---|
| 循环 | 最后一步回到第一步，**并且会反复运行** | 环形箭头（3–6 节点）、飞轮 | 画成清单；把并列维度或能力放在环上 |
| 比例 / 构成 | 合计 100%，读者关心份额 | 项目少用饼或环；项目多用 100% 堆积或树图；两维市场结构用 Marimekko | 合计不是 100%；定性占比画成饼 |
| 流程 | 固定先后，到终点结束 | 横向箭头链（3–6 步）；多方交接用泳道；有分支用流程图 | 画成环；画成无方向卡片 |
| 阶段演进 | 同一维度逐级升高 | 阶梯、逐级加高的台阶或圆柱 | 平铺等高；并列选项画成阶梯 |
| 层级依赖 | 出现"底座、基础、前提、上限、支撑" | 金字塔、层叠、战略屋（自下而上） | 平铺三栏 |
| 甘特 | 任务各有起止、可并行 | 甘特条 | 给高层看方向时用甘特（应该用路线图） |
| 路线图 | 多条工作线、中长期、精度到季度 | 泳道加阶段块加旗标 | 精确到天的任务清单 |
| 战略图 | 战略屋：愿景—支柱—地基；战略地图：四层自下而上驱动；OGSM：四列表 | 约定图形，结构不能乱改 | 支柱间画箭头、战略地图箭头向下、OGSM 画成环 |
| 多方 × 多维 | 3 个以上对象 × 3 个以上维度 | **表格**（哈维球、数值、小条形） | 环、雷达（雷达的形状随轴的顺序改变） |
| 漏斗 | 同一批对象逐层递减 | 漏斗（层宽按数据）或递减横条 | 不同批对象、数量上升 |

### 4. 部件的含义（视觉语法）
依据：Bertin 视觉变量、格式塔原则、Tversky 的图式元素、Lakoff 的"多即上、好即上"。共整理了 23 种部件。最容易出错的几种：

| 部件 | 读者读出 | 只有这种内容才能用 |
|---|---|---|
| 环、回环箭头 | 周而复始 | 真的回到起点并反复运行 |
| 汇聚箭头、光束 | 共同导致、推出中心结论 | 各项确实共同产生同一个结果 |
| `>>>`、两块之间的大箭头 | 左边转变成或推出右边 | 确实是转变或推导 |
| `+` 号 | 叠加后构成整体 | 相加确实构成整体 |
| 大小、明度不同 | 更重要或更多 | 有主次或数量；等权项必须同尺寸 |
| 逐级加高 | 递进、规模变大 | 同一维度逐级升高，有数值时按比例 |
| 上升箭头 | 增长、改善 | 风险页禁用 |
| 颜色 | 好坏 | 箭头方向跟数值，颜色跟好坏：成本下降是好事，用向下箭头配好色 |

### 5. 复合页面
- 主图示就是直接证明标题的那个关系。
- 次要关系只用弱部件（表格、行对齐、标注），不再加第二套箭头或环。
- 关键数字贴在主图的对应位置。
- 一一对应的映射用行对齐表达。
- 强调色只用一处。

上限是一个主图、一个次要元素、一个结论条。放不下时调整版面，不删大纲。

## 四、页面分区与模块组合（要点）

详细内容在 Skill 的 `references/page-zoning.md`，研究笔记在 `runs\20261027-0842_logic-research_rnb\research-page-zoning.md`。

1. **咨询页的必备区只有三个**：行动标题、一个主图示、来源和页码。导语、侧栏、结论条都是可选的。
2. **栅格以参考稿实测为准**。rnb-core 的内容区是 x 36–1244、y 101–672，按 12 栏切分：栏宽 86，栏间距 16，步长 102。`prepare_reference.py` 现在会自动测出这个栅格，写进 `grid.txt`。研究笔记里的"边距 64px"是通用推算值，没有采用。
3. **10 个分区模板**：
   - Z1 主图 + 侧栏（8+4）
   - Z2 左右（6+6）
   - Z3 左文右图（4+8）
   - Z4 上卡条 + 下主图
   - Z5 三栏
   - Z6 2×2
   - Z7 主图 + 数字堆叠
   - Z8 中心聚焦（3+6+3）
   - Z9 上主下次
   - Z10 左数字栏 + 主图（3+9）

   每个模板都写了在 rnb-core 上的坐标，以及适合的主关系。
4. **面积规则**：主模块占主体区的 55–70%；单个次模块不超过主模块的 1/2；每页最多 4 个模块。依据是 NN/g 的视觉层级研究、StrategyU 和 Deckary 的版式惯例；具体比例是推算值。
5. **拼贴感的来源是规格不一致，不是模块太多**。这一点来自 think-cell Library 的"目标格式"做法。组合后要逐页核对六项：栅格对齐、层级、规格、配色角色、关系、3 秒测试。
6. **挑模块的顺序**：
   1. 起页后完好
   2. 逻辑编号匹配
   3. 单元数在可增删范围内
   4. 逐条核对部件含义
   5. 不命中"不能用于"
   6. 缩放比在 0.8–1.25 之间
   7. 风格相近

## 六、研究中发现并修复的底层问题

| 问题 | 发现方式 | 处理 |
|---|---|---|
| **起页后与原稿不一致**：第 33 页的立体光环是三维旋转效果，导入后丢掉了旋转，变成覆盖半页的大圆环。以前选图看的是原稿截图，看不出来 | 拼页测试 | `prepare_reference.py` 现在会把能通过检查的起页结果导出并渲染到 `started-renders/`（rnb-core 有 55 页），选模块以它为准。模块目录加了 `start_level` 字段（完好、可用、结构损坏、未验证） |
