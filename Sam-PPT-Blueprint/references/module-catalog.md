# 模块目录 modules.json（参考稿库里只做一次）

参考稿的每一页拆成若干**模块**：版面上一块能独立表达一层意思的矩形区域，例如"左侧漏斗""中间 4 张数据卡""底部时间轴""右侧结论栏"。做页面时，一页可以由来自不同参考页的模块拼成（`compose_page.py`）。目录写好后要经用户审定，审定前在运行日志里注明"模块目录未经审定"。

## 怎么拆

- 看两套渲染图：`renders/slide-NN.png` 是参考稿原貌，`started-renders/slide-NN.png` 是导入、起页后的实际效果。**判断模块能不能用，以后者为准**；有的效果导入后会变形，比如三维旋转会丢失。
- 坐标用 `python scripts/edit_page.py list <import>/authoring-svg-flat/slide_NN.svg`，每行给出 `id 类型 frame=x y w h 文字`。渲染图是 1600 px 宽，SVG 坐标 = 像素 × 0.8。
- 模块 = `bbox=[x,y,w,h]`。`compose_page.py` 只搬**整个外框都在 bbox 内**的顶层元素（容差 6 px），所以 bbox 要把这个模块的底板、装饰、文字都包进去，又不能包进相邻模块。划完后用 list 的 frame 核对。
- 页头页脚不算模块，它们由外壳页提供。
- 一页通常拆 2–5 个模块；整页只有一个大图示时就是一个模块。主要靠照片、logo 墙、截图撑起来的块，记 `image_dependence: "高"`，不细拆。

## 字段

```json
{
  "page": "07",
  "module": "07-B",
  "bbox": [600, 195, 400, 345],
  "role": "主图示 | 次图示 | 数据卡组 | KPI大数字 | 文字栏 | 结论条 | 导语条 | 原生图表 | 表格 | 时间轴 | 图片位 | 装饰",
  "diagram": "图示词表中的一个，没有合适的写 其他:说明",
  "logic": ["B3"],
  "units": "环上节点 6（4–7）",
  "chars": 120,
  "parts": [
    {"part": "环上的弧形箭头", "means": "依次循环、回到起点", "if_not_true": "删"},
    {"part": "中心深蓝圆", "means": "所有节点围绕的核心", "if_not_true": "改成结果数字或删"}
  ],
  "fits": "适合放什么内容",
  "not_for": "最容易犯的误用",
  "image_dependence": "低 | 中 | 高",
  "style": "配色、立体感、阴影、渐变（一句话）",
  "dependency": "是否依赖同页其他模块；没有写 无",
  "start_ok": true,
  "start_note": "起页后变了什么；没有写 无",
  "start_level": "完好 | 可用 | 结构损坏 | 未验证",
  "bbox_extra": [0, 0, 0, 0]
}
```

- `start_level`：`完好` 指起页后与原稿一致。`可用` 指只缺照片或 PNG 图标，或者参考稿原文不换行、竖排变横排；这些在换成大纲文字、补图标后会消失，但竖排文字要改成横排或手动换行。`结构损坏` 指图形本身坏了，例如三维效果丢失、图表数据系列消失、渐变光束变成硬边，这种模块不能用；其中只有原生图表重排的，可以只取外框，再按大纲数据重画图表。`未验证` 指没有起页渲染图，用之前先单页起页并渲染确认。
- `bbox_extra`：可选。一个矩形框不全的 L 形模块，用第二个框补上，`compose_page.py` 写作 `NN:x,y,w,h+x2,y2,w2,h2@X,Y`。
- `dependency`：`compose_page.py` 只搬中心在框内、且至少 60% 页面面积在框内的元素（旋转 90° 的形状按它在页面上的样子算）。与相邻模块共用的矩形或圆角矩形底板，会自动裁成框的大小带过来；其他会留在原处的东西（不规则的共用底形、跨模块连线）写在这里。
- 写完后运行 `python scripts/check_modules.py <modules.json> <import>/authoring-svg-flat --write`。它核对每个模块实际会搬走多少元素、哪些元素被留下、`logic` 编号是否合法，并自动写入三个字段，生成 `modules-index.txt`（一行一个模块，供人浏览；做页面时不通读它，按分区用 `pick_modules.py` 取候选）：
  - `texture`：模块里带渐变、阴影、半透明的形状数和形状总数；
  - `texture_level`：按"3×渐变 + 3×阴影 + 0.5×半透明"在全目录里三等分得到的高、中、低；
  - `backplates`：会一起带过来的共用底板数。
- `parts` 里只列**关系部件**（会让读者读出单元之间关系的东西）；渐变底、阴影、光斑、底板等装饰不用列，它们默认保留。

- `logic`：填 `logic-diagrams.md` 第二节的编号，1–2 个，表示这个模块的图形**天然**表达的关系。另有两个非关系编号：`K` 表示关键数字（大数字、数据卡），`S` 表示结论或导语强调。
- `parts` 是重点：把模块里每个带含义的可见部件都列出来（箭头方向、环、连线、汇聚箭头、`>>>`、光束、`+`、上下箭头、颜色对比、大小递增、对称、编号、中心圆、语义图标），写清读者会读出的意思，以及内容不满足时是删还是改。
- **图示词表**：并列卡片、编号列表、图标要点、箭头链流程、曲线旅程、时间轴、阶梯、循环环、中心辐射、韦恩交集、矩阵表格、2×2象限、金字塔、漏斗、树状层级、房屋框架、左右对比、天平权衡、原生柱图、原生条形图、原生折线图、原生饼环图、KPI大数字、进度环或仪表、价值曲线、流向汇聚、地图、立方体、引语、图片位、导语条、结论条。

## 用法

第 2 步按 `page-zoning.md` 第四节、用 `pick_modules.py` 从目录里挑模块；第 3 步把选中模块的 `bbox` 交给 `compose_page.py`。目录里的 `parts` 就是第 4 步改页时逐个部件核对的清单。
