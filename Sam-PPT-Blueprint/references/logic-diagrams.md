# 逻辑表达规范：什么关系用什么图示（第 2 步用）

先有要说的话，再定关系，最后选图（Zelazny：信息 → 比较类型 → 图形）。**图形部件本身就是陈述**：箭头说"有方向"，环说"会回到起点"，金字塔说"下层撑起上层"，大小说"更重要或更多"。换图形就是换说法，所以内容里没有的关系，图上不能画。拿不准时，退回最中性的形式：并列卡片或表格。

本文件只管**定性关系的图示和部件含义**。有数据的图表类型，见 ppt-master 的 `<PM>/templates/charts/chart-vocabulary.md`（33 种）；表格见 `<PM>/templates/tables/table-vocabulary.md`。ppt-master 的六个关系原子（order、link、parent、membership、contrast、overlap，见 `<PM>/references/executor-structure.md`）在下表最后一列给出对应。

## 一、先给每页填"内容结构卡"

选图之前，对大纲的每一页逐项填写，写进 plan.md：

| 项 | 怎么填 |
|---|---|
| 结论 | 标题那句话证明的是什么（一句话） |
| 单元 | 有几个对象、步骤、阶段或要素（数清楚） |
| 维度 | 单元之间按几个维度比较；没有比较写 0 |
| 方向 | 有没有先后。调换单元顺序后意思变不变？ |
| 闭合 | 最后一个会不会回到第一个，并反复运行？ |
| 权重 | 单元是否等权？有没有"底座 / 基础 / 前提 / 上限 / 支撑 / 核心"这类依赖词？ |
| 数量 | 有没有决定图形尺寸的数值？是否逐级递减？是否合计 100%？是否随时间变化？ |
| 好坏 | 每个数字变化是好还是坏（决定箭头颜色，见第四节） |
| 次要信息 | 关键数字、一一对应的映射、案例、建议各有几条 |

然后按第二节的判断标准认定**主关系**（直接证明结论的那个，一页只有一个）和**次要关系**（最多一个）。

## 三、部件含义与删改规则

### 先分清两类部件

参考稿的质感（"神韵"）大多来自**装饰**，要保留；删改规则只管**关系部件**。

| 类 | 是什么 | 怎么处理 |
|---|---|---|
| **关系部件** | 会让读者读出单元之间关系的东西：箭头、环、连线、汇聚或发散的形状、`>>>`、`+`、编号、阶梯和逐级加高、金字塔层序、大小或明度差异、中心位置、强调色、上下箭头、语义图标 | 按下面的删改规则逐个核对，含义不成立就删或改 |
| **装饰** | 不连接任何两个单元、不区分单元高低的东西：渐变底、阴影、半透明光斑、光晕、底板和面板、柔光条、立体圆柱或台面的光泽、细分隔线、角标花纹、水印式大字的底形、页头手形 | **一律保留**，只换颜色时也保持原来的渐变和透明度；只有挡住文字、或在风险页表达"增长"时才动 |

同一种形状要看它在页面上做什么：光束如果把两侧几块连到中心，就是关系部件（说"两侧推出中心"）；如果只是铺在一块后面当背景光，就是装饰。拿不准时，问一句"删掉它，读者对单元之间关系的理解会变吗？"——不变就是装饰，保留。

**删掉关系部件时，不要连带删掉它下面的底板和光效**；关系部件删掉后留下的空位，用相邻模块收拢，或保留底板放说明文字。

### 部件 → 读者会读出什么

| 部件 | 读者读出 | 只有内容满足下列条件时才能用 |
|---|---|---|
| 单向箭头 | 先后、因果、转化、流向 | A 确实在 B 之前，或确实导致或转化为 B |
| 双向箭头 | 相互作用、可逆 | 两边确实相互影响 |
| 回环箭头、环 | 周而复始 | 最后一步回到第一步，并反复运行 |
| 汇聚箭头（多 → 一） | 共同导致、合并 | 各项共同产生同一个结果 |
| 发散箭头（一 → 多） | 派生、拆分 | 一个来源确实产生多个去向 |
| `>>>`、大箭头放在两块之间 | 左边转变成右边、左边推出右边 | 两块之间确实是转变或推导 |
| 光束、扇形连接（把多块连到中心） | 两侧推出中心结论 | 中心确实由两侧推导而来（只铺在一块后面的背景光是装饰，保留） |
| 无箭头连线 | 有关联 | 两者确实有关系 |
| 包含、嵌套 | 属于、子集 | 内层完全属于外层 |
| 重叠 | 共享部分 | 交集确实存在并值得说 |
| 上下位置 | 上 = 高层、结果、更好；下 = 基础、前提 | 有层级或依赖；等权项要排在同一水平线上 |
| 左右位置 | 左 = 先、旧、原因；右 = 后、新、结果 | 有先后；对比时左边是现状或对手 |
| 中心位置 | 核心、被围绕的对象 | 中心项确实统领四周 |
| 大小、明度不同 | 更重要或更多 | 有数量或有主次；等权项必须同尺寸、同明度 |
| 阶梯、逐级加高的圆柱 | 递进、升级、规模变大 | 同一维度上逐级升高；有数值时高度按比例 |
| 金字塔、层叠 | 底部是基础，顶部是目标；有时被读成数量比例 | 有依赖或层级 |
| 编号 1-2-3 | 顺序或优先级 | 有先后或排序；纯并列项改用图标或项目符号 |
| `+` 号 | 叠加后构成整体 | 各项相加确实构成一个整体 |
| 左右镜像 | 对等、可比 | 两边维度对齐 |
| 强调色、单独标红的一块 | 看这里，是重点 | 每页只给结论对应的那一处 |
| 上升箭头、上升曲线 | 增长、改善、机会 | 内容确实在增长或改善 |
| 下降箭头 | 减少，常被联想为变差 | 数值确实下降 |
| 圆的大小（时间轴节点、气泡） | 重要程度或数量 | 有对应的重要性或数值 |

### 删改规则（逐页逐个部件核对）

1. **环**：最后一项不回到第一项、也不会反复运行 → 删掉环，有先后的改成横向流程，无先后的改成并列卡片。
2. **箭头**：两项之间说不出"先后、因果、转化、流向"中的任何一种 → 删掉。
3. **双向箭头**：只有单向影响 → 改成单向。
4. **汇聚、发散箭头、连接各块的光束**：各项并不共同产生一个结果，也不是从同一来源派生 → 删掉。
5. **编号**：调换顺序不改变意思 → 删掉编号，改用图标。
6. **阶梯、逐级加高**：各项不在同一维度上逐级升高 → 改成等高。
7. **金字塔、层叠**：上层不依赖下层 → 改成并列。反过来，内容有依赖词 → **必须**用层叠，自下而上。
8. **大小、明度不同**：各项等权 → 统一。
9. **高低不同的柱、圆柱**：没有对应数值，或高度不成比例 → 改成等高，或按数据重算。
10. **韦恩**：交集里写不出具体内容 → 改成并列；子集关系 → 改成嵌套。
11. **漏斗**：不是同一批对象，或数量不是逐级递减 → 改成条形或流程；是漏斗时层宽按数据收窄。
12. **连线**：两项之间没有关系 → 删掉。
13. **雷达、把维度画在环上**：维度不是同一量纲，也没有周期性 → 改成表格或分组条形。
14. **上升箭头、增长曲线装饰**：页面主题是风险、问题或下滑 → 删掉。
15. **强调色**：一页里超过一个焦点 → 只留结论对应的那一处。
16. **中心位置**：中心项并不统领四周 → 取消中心，改成网格。
17. **参考稿自带的语义图标**（购物车、房子、人物等）：图标意思和这一页内容不符 → 换成和内容对应的图标；页头手形这类装饰性图标保留。

## 四、箭头方向和颜色

**箭头方向跟着数值走，颜色跟着好坏走。**

| 情形 | 箭头 | 颜色 |
|---|---|---|
| 收入、效率上升（好） | ↑ | 好色 |
| 成本、时长、故障率下降（好） | ↓ | 好色（**不能用坏色**） |
| 收入下滑（坏） | ↓ | 坏色 |
| 风险、成本上升（坏） | ↑ | 坏色 |

plan.md 的全稿约定里要写明哪个颜色是好色、哪个是坏色。一般商务稿用品牌主色表示好，警示色（红、橙）表示问题。中国大陆的财务和股市语境里红色表示上涨，遇到这类稿件要先确认。标题写"改善"，图上就不能出现坏色的箭头。

## 五、复合页面

1. **一页只证明一个结论**，主图示就是直接证明标题的那个关系。
2. **次要关系只用弱部件**：表格、行对齐、标注、并列卡片。不再加第二套箭头、环或层级，否则两套视觉语法会打架。
3. **关键数字**要么是结论本身（写进标题，或做成主图上的大号标注），要么作为标注贴在主图的对应位置；不要另起一块去抢焦点。3–4 个并列数字放成一排数据卡。
4. **一一对应的映射用行对齐表达**（同一行，加细线或同色），不画交叉箭头。例如漏斗右侧放"卡点 → 解法"，每一行对齐漏斗的一层。
5. **焦点唯一**：强调色只给证明结论的那个元素。
6. **上限**：主图 + 一个次要元素 + 结论条。放不下时调整版面，**不删改大纲内容**。
7. **阅读顺序与逻辑顺序一致**：从左到右、从上到下；结论放在终点（右侧或底部）。
