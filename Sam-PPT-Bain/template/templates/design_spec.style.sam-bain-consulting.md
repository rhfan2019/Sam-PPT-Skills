# Sam 蓝红咨询构图 — Style Specification

> Method and design defaults only. No project communication contract, brand identity, page structure, or SVG prototypes.

## I. Style Overview

| Property | Value |
|---|---|
| Style Name | Sam 蓝红咨询构图 |
| Best Fit | 中文行业研究、咨询白皮书、经营诊断与方案汇报中需要"一页讲清一个判断并给出证据"的正文页，既用于讲解也用于会后精读 |

## II. Communication Method

- **Preferred Mode**: pyramid
- **Argument Flow**: 先确定全篇要回答的问题和总答案，再拆成若干支撑论点，每个论点落到一页；保持"总答案 → 支撑论点 → 页面结论 → 证据"的可追溯链。顺序服从当前项目，不套固定页序。
- **Page Message Discipline**: 每页标题必须是结论句（不是话题词）；页面若使用论点条，论点条写本页的 so-what，与标题互补、不重复标题措辞。一页只回答一个问题，页面上只有一个主角。
- **Claim Discipline**: 事实、推算、判断、建议分开表述。只使用大纲/资料中存在的事实，**不替原文添加修饰或新事实**；由原始数据推算出的数字（同比、份额、差值、转化率、均值、倍数）可以用来提高信息密度，但必须标明是推算值，并在交付时逐条列出供核实。

## III. Page Role Vocabulary

构图倾向写的是"借哪种构造"，不是固定版式：整页布局、模块数量和位置按本次大纲重排。括号里是可参照的样张。

| Role | Communication Job | Evidence Obligation | Composition Tendency |
|---|---|---|---|
| 主视觉 + 两翼 | 一个核心概念向两侧展开为"是什么"和"意味着什么" | 两侧条目都能追溯到大纲 | 主视觉占左半页、是全页最大的图形：深色环加白色外晕，节点大圆压在环上形成跨界；一束扇形淡光把主图和中间列连成一体；中间列用立体标签（顶面浅、正面深）；右栏只用一个细虚线框，不加深色栏头（sample-01） |
| 中心辐射 / 平台 | 说明一个核心如何由多个部分共同支撑 | 每个部分给出一个代表性指标或特征，不编造 | 发光的椭圆平台做核心，节点圆放在椭圆轨道上，轨道上写关系词；深色只出现在一侧的维度栏和另一侧的效果栏，中间全是浅色和渐变（sample-02） |
| 层级 / 分层 / 外扩 | 说明由低到高或由内到外的层次 | 每层给出决定性特征 | 金字塔或半圆分层，同色相由深到浅渐变；数据标签用箭头形压在层的边上；子项小圆压在层与层的分界线上；需要时两侧各放一个英雄数字配竖向箭头，底部用编号时间轴收束（sample-03、04） |
| 二元对比 | 帮读者在两个选项或两种模式之间做判断 | 对比维度、单位、口径一致 | 一个双色大圆（左蓝右红）加两条弧形箭头表示互相转化，两翼条目沿弧线排列、用圆点接到弧上；数据对比用背靠背条形，中间放类目，顶部一个超大数字点题（sample-05、12） |
| 链路 / 时间推进 | 说明阶段如何推进、关键节点在哪 | 阶段与节点来自大纲 | 一串大小不一的圆沿一条起伏的弧线排列，关键节点更大；顶部编号虚线时间轴对齐；阶段之间用箭头串联（sample-06） |
| 框架 / 战略屋 | 把方案收束为一个整体结构 | 每个构件对应大纲内容 | 屋顶只是一条细线，标题块压在屋脊上；区块标题压在细线框的框线上；整页只有两处深色块（屋脊标题、底座）；行名用浅色大字而不是色块；大量留白（sample-07） |
| 矩阵 / 定位 | 用两个维度切出不同情形并给出对应选择 | 维度定义清楚；落入各象限的依据可追溯 | 元素少：坐标轴、格子、每格一个图形符号和一对数据；象限含义直接写在格子里；格子之间、格子内部都留足白；侧栏和矩阵之间只用一支红色引线连接（sample-08、10） |
| 趋势 / 排名 / 分布等数据页 | 用数据证明一个判断 | 原始数据逐点标注；推算值单列在交付说明 | 图表本身就是主视觉，按"突出一个、其余退后"处理：关键系列或关键柱用砖红或深海军蓝，其余用浅蓝灰；曲线或阶段的含义直接写成批注（带括号、箭头、指向具体数据点）；条形细长、数值标在条尾；可在图旁放一个"倍数卡"（英雄数字 + 一句话）先给结论；用红色虚线箭头把发现引到说明（sample-09、10、11） |
| 转化漏斗 | 指出流程中最弱的一环 | 各阶段占比、相邻转化率与流失率由数据算出 | 中央立体切面漏斗（每层左右两半深浅不同，最弱层砖红）；阶段定义和转化诊断分列两侧，用圆点虚线接到对应层 |
| 结论与建议 | 把全篇判断收束为可执行的举措 | 每项建议对应前文证据 | 战略屋或举措矩阵：愿景 + 支柱 + 基础，深色只给屋脊和底座 |

样张里没有的数据图（瀑布、Marimekko、龙卷风、甘特、热力、箱线、RACI 表）沿用数据页的通用手法：图上直接批注关键点，只突出一两个数据，条形细长，留白。

## IV. Evidence & Data Expression

- **Argument Trace**: 每页证据要能指回本页结论。证据框是可选配角，只放本页正文没出现过的新信息（推算值、跨页引用），不重复图上已有数字，没有新信息就不放。
- **Charts**: 图表优先用 PowerPoint 原生可编辑图表或原生形状。每个数据点直接标值，能省则省坐标轴与网格线；**每张图只用一种强调色标出要读者看的那一个点**（关键柱、关键系列、最弱环节），其余系列退到海军蓝浅阶或灰色；用参考线、阶段底色带和批注（尖角或箭头落在具体数据点上，写出"这里发生了什么"）讲故事。柱线组合时折线浮在柱子上方，避免标签互相遮挡。
- **Tables**: 列与行由比较逻辑决定；表格用细横线分行，不给每个单元格铺底色；只给焦点行或焦点列一条浅色底带或砖红细框，关键单元格红色加粗；表头可用深色。
- **Sources**: 页脚左下写免责声明或数据来源；示例数据必须注明"示例数据"。推算值在交付说明中逐条列出。
- **Native Editability**: 文字、图表、表格、形状全部保持可编辑；不使用截图替代图表。

## V. Visual System Defaults

- **Preferred Visual Style**: custom
- **Visual Style Behavior**: 一份精致的咨询信息图，不是数据仪表盘。白底正文页，海军蓝为主色、砖红为强调与"另一侧"语义。**每页一个主角**：一个有体积感的主视觉（同色相渐变、白色外晕、柔和阴影、分层深浅）占正文区约一半，是全页最大、最重的图形，可以跨过区块边界、与配角交叠（节点压在环上、标签压在层边、徽章压在节点边）。**配角围绕主角**：其余内容作为 2–4 组配角排在主视觉周围，浮在版面上，用圆点虚线、弧形箭头、右箭头、编号和批注接到主视觉上，而不是各自装进等大的卡片。**分区靠构件**：大区和并列对象用 Skill 构件库（`references/components/kit.md`）里的页签 + 浅底面板、竖排侧标签条、人字箭头色带、立体标签来划分和命名，深色出现在这些构件和主视觉上，每一处深色都标出一个真实的大区或对象；不要给每个小模块顶一条深色栏头，也不要放没有含义的深色装饰块。模块内部再细分时用 1 px 浅色细线框、虚线框或留白。**留白有意**：主视觉四周、大区之间的成片留白是呼吸感，不要用胶囊、规则条、说明条或淡色装饰去填。论点条按版式可选。
- **Composition**: 内容区以标题线两端为左右边界，任何元素不得越界，全宽元素两端贴齐边界。先定主角（按大纲内容之间的关系选构造，见 §III），再安排配角，最后决定是否需要收束元素（底部箭头带、编号时间轴、"A ⇄ B"框架条），只有内容里确有这种关系时才加。同一行的标题、箭头、标签框、说明共用一条中线；上下相邻的列左右边缘对齐。不要用 N 个同尺寸模块等分并排作为整页结构。**一条阅读主线**：整页一个阅读方向，区块不超过 4 个，区块之间用大号人字箭头、右箭头、加号或带箭头的引线串起来。**同级内容同一单元**：并列项用完全相同的单元重复排列，一页单元写法不超过 3 种。**焦点少**：大数字整页不超过 3 个，英雄数字最多 1 个。**栏距统一**：区块间距 12–16 px，单元内边距不小于 12 px。**每页至少用构件库里的 2 种构件**：构件可以逐页复用，变化的是构件的组合、位置、大小和数量；相邻两页不要用同样的构件组合摆同样的位置。
- **Density**: 文档级密度，内容完整但不挤。标题 37 px，论点条约 27 px，焦点（英雄数字 48–64 px 或英雄关键词 24–32 px）每页 1–2 个，条目标题约 17–21 px（粗体并着色），正文/说明约 13–15 px，单位与注释约 10.7–12 px 且少用。一条信息 = 粗体标题 + 说明，图标圆和标签框按需加，不是每条都要配齐。内容铺到正文区下缘，底部不留整条空带，模块内部不留空洞。
- **Decoration**: 同色相渐变（海军蓝 #16365F → #2E5A94，砖红 #8E2B1D → #C0503E）、白色外晕和柔和阴影**只用在主视觉和浮起的节点上**；虚线用于连接线、引线和模块框；弧形箭头串联链路；批注用括号、箭头和短句直接写在图上。避免：卡片墙、每个模块顶一条深色栏头、与内容无关的装饰图标、大号淡色编号或水印字、用胶囊和规则条填空。
- **Color Behavior**: 左侧/用户侧/现状用蓝系，右侧/策略侧/判断用红系，颜色表达"属于哪一侧"而不是装饰；数据图里砖红只标要读者看的那一个点；红色面积约不超过全页 20%；深色底上不放浅色小字。已安装的 Deck 身份（sam-bain）提供确切色值。
- **Typography Character**: 一个无衬线家族的多个字重：标题最粗、标签中等、正文常规、数字粗体；层级靠字重、字号与对齐，而不是靠框。
- **Recognition Test**: 把渲染图缩到缩略图大小，第一眼落在主视觉上，能说出"这页的主角是什么"；能认出至少 2 种构件库构件。
- **Anti-mood**: 数据仪表盘、等分卡片墙、后台管理界面、每块顶着深色栏头的表单页、由脚本批量排出的整齐格子页。

## VI. Image & Icon Direction

- **Image Usage**: 默认不用图片，主视觉和质感用原生形状与渐变构建；图片只在提供证据或必要语境时使用，抠图类物体可压在主图或核心圆下方增加层次。
- **Image Treatment**: 背景照片四周渐隐到白底；不在图片里放合成文字。
- **Icon Treatment**: 一页只用一个图标家族，统一着色：节点圆内放白色图标，标签旁的小图标用主色或强调色；图标只用于说明角色、状态或关系，不做装饰。

## VII. Review Focus

- 缩略图上第一眼落在主视觉上；主视觉有体积感（渐变、外晕、阴影或分层），占正文区约一半。
- 每页至少用了 2 种构件库构件，写法和比例与构件库一致；每一处深色都标出一个真实的大区或对象；没有等分卡片墙。
- 配角都用连线、箭头、编号或批注接到主视觉上；数据图只突出一个点并有图上批注。
- 所有内容元素都在标题线两端（35.93 / 1244.07 px）之内，全宽元素两端贴齐；同一行共用中线，相邻列边缘对齐；无文字溢出、遮挡或数字与单位分行。
- 标题是结论句，论点条与标题互补；同一数字在一页上只出现一次。
- 底部没有整条空带、模块内部没有空洞；主视觉四周的留白没有被胶囊、规则条或装饰填掉。
- 推算数字已标明并在交付说明中列出。
